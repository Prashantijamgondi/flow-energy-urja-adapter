# Flock Energy — Urja Meter Ops API

A clean REST API wrapper around the legacy "Urja Meter Ops" portal, which has no API of its
own. This service handles login/session management against the portal internally and exposes
tidy, documented JSON endpoints instead.

## What this is

- `app/client.py` — the adapter that talks to the legacy portal: handles login, session cookies,
  re-authentication on expiry, and (if needed) HTML parsing into structured data.
- `app/main.py` — the FastAPI app exposing the clean REST endpoints.
- `app/models.py` — response schemas (Pydantic).
- `app/config.py` — environment configuration.
- `PROTOCOL.md` — how the legacy portal actually behaves, discovered via DevTools.
- `openapi.json` — the OpenAPI 3.0 spec for **this** API (not the portal's).

## Endpoints

| Method | Path | Description |
|--------|------|--------------|
| GET | `/health` | Service health check |
| GET | `/api/v1/meters` | List all smart meters |
| GET | `/api/v1/meters/{id}` | Get a single meter's details |
| GET | `/api/v1/meters/{id}/consumption` | Get a meter's consumption history |
| GET | `/api/v1/hierarchy` | *(optional extension)* Network hierarchy tree |

Interactive docs are served at `/docs` (Swagger UI, auto-generated by FastAPI) and the raw spec
at `/openapi.json`.

## Setup

```bash
git clone <your-repo-url>
cd flock-energy-api
python -m venv venv
source venv/bin/activate  # or venv\Scripts\activate on Windows
pip install -r requirements.txt
cp .env.example .env      # fill in credentials if not using defaults
uvicorn app.main:app --reload
```

Service runs at `http://localhost:8000`.

## Sample requests

```bash
curl http://localhost:8000/health

curl http://localhost:8000/api/v1/meters
```

## Design decisions & trade-offs

- Used a single persistent `httpx.Client` per process to hold cookies, rather than a session
  pool — simplest thing that works for a read-only internal tool with modest concurrency.
- Chose to normalize numeric strings (e.g. `"124.50"` → `124.50`) and let malformed values pass
  through as `null` rather than raising, so one bad record doesn't break a whole list response.
